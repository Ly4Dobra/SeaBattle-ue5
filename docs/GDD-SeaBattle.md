# ГДД: «Морской бой» (SeaBattle) — этап 1 роадмапа

> Жанр: пошаговая стратегия / классическая настольная игра. Платформа: PC (UE 5.5).
> Роль проекта: **учебный** — фундамент UE5/C++ + сеть. Команда: 2 человека.
> Статус: в разработке (М1–М5, сент 2026 – янв 2027).

---

## 1. High Concept

Классический «Морской бой» на поле 10×10, в который играют **два игрока по сети** (listen server).
Проект — учебный полигон: на нём отрабатываются Gameplay Framework, репликация, UMG и чистая C++-логика под тесты.

**Elevator pitch:** «Тот самый морской бой из детства, но с другом через сеть — и написанный на C++ так, что вся логика покрыта юнит-тестами».

## 2. Цели проекта

1. **Обучение**: Модуль 4 (отражение) → Модуль 5 (Gameplay Framework) → сеть.
2. **«Японский козырь №2»**: вся игровая логика (поле, корабли, правила, попадания) — чистый C++ без UE-зависимостей → покрывается gtest.
3. **Портфолио**: готовый, упакованный проект с README, скриншотами и видео.

## 3. Правила игры (классика)

- Поле **10×10** (координаты A–J × 1–10).
- Состав флота: 1× четырёхпалубный, 2× трёхпалубных, 3× двухпалубных, 4× однопалубных (всего 10 кораблей, 20 клеток).
- Корабли ставятся **горизонтально или вертикально**, не касаясь друг друга (в т.ч. углами).
- Ход: игрок называет клетку. «Мимо» — ход переходит. «Попадание» — ходит снова.
- Корабль считается **убитым**, когда все его палубы подбиты; убитый корабль обводится «полем мёртвых клеток».
- Победа: все корабли противника уничтожены.

## 4. Игровой цикл

```
Меню → Лобби (создать/присоединиться) → Расстановка флота → Бой (ходы) → Экран победы → Реванш/В меню
```

1. **Меню**: имя игрока, «Создать игру» (listen server), «Присоединиться» (IP/Steam).
2. **Расстановка**: drag/клик — выбрать корабль, повернуть (R), поставить. Автопроверка правил.
3. **Бой**: поочерёдные ходы, подсветка попаданий/промахов на обоих полях (своё и «чужое»).
4. **Победа**: экран результата, кнопка «Реванш».

## 5. Архитектура

### Слой 1 — Чистая C++-логика (без UE, тестируется gtest)

| Класс | Ответственность |
|---|---|
| `FShip` | палубы, состояние (цел/ранен/убит), проверка уничтожения |
| `FCell` | координата, статус (пусто/корабль/попадание/промах) |
| `FBattleField` | сетка 10×10, расстановка, валидация правил, выстрел |
| `FBattleRules` | состав флота, проверки касаний, проверка победы |
| `FGameSession` | состояние партии, очередь хода, счёт |

> Принцип: модуль `BattleCore` (namespace + structs) — **ноль зависимостей от UE**, чистый C++17/20.
> gtest запускается как консольный экзешник без редактора — это и есть «японский козырь №2».

### Слой 2 — UE-обвязка (движковый слой)

| Класс | Роль |
|---|---|
| `ASeaBattleGameMode` | правила партии, кто ходит, конец игры |
| `ASeaBattleGameState` | реплицируемое состояние: поля, очередь хода, счёт |
| `ASeaBattlePlayerController` | ввод, обработка хода, RPC |
| `ASeaBattlePawn` | минимальная «фигура» игрока (камера/вид сверху) |
| `UBattleFieldWidget` | UMG: два поля, клетки, подсветка |
| `AMenuPlayerController` | меню/лобби (или отдельные виджеты) |

### Сеть (Listen Server)

- Хост = listen server, клиент подключается по IP.
- **Авторитет**: все решения о попаданиях принимает сервер через `BattleCore`.
- `GameState` реплицирует: расстановку, статусы клеток, очередь хода.
- RPC: клиент → сервер «выстрел», сервер → клиент «результат».
- Очередь хода защищена на сервере (клиент не может «ходить не в свой ход»).

## 6. UI/UX

- Главное меню: заголовок, кнопки «Создать игру» / «Присоединиться», поле ввода IP.
- Лобби: список игроков, кнопка «Начать» (только у хоста).
- Поле боя: сетка 10×10; клетка подсвечивается при наведении; клик — выстрел.
- Цвета: синий (вода), серый (промах), красный (попадание), чёрный (убит).
- Индикатор «Ваш ход / Ход противника», счётчик оставшихся кораблей.

- [ ] Два игрока играют по сети полную партию до победы

- [ ] gtest зелёный (BattleCore покрыт)
- [ ] Сборка не падает, игра запускается с одного клика
- [ ] README + скриншоты + видео в репозитории
